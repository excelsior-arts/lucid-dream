# Adding a voice

Both engines clone zero-shot from a single reference clip. There is no training
step: you drop in a wav, point a persona at it, and that is the voice.

Use audio you have the rights to. A voice is a real person's, even when the
character speaking is fictional.

## The short version

```sh
# 1. cut the best reference window out of any audio, checked as it goes.
#    Name it after the persona that will speak with it.
python tools/voiceprep.py source.mp3 nova     # -> voices/nova.ref.wav

# 2. restart, pick that persona, talk
```

## The targets

Chatterbox slices the reference by **hard prefix**, so where the good part sits
in the file decides whether it is used at all:

```
ENC_COND_LEN = 6s    the encoder that drives DELIVERY  -> first 6 seconds only
DEC_COND_LEN = 10s   the decoder that carries TIMBRE   -> first 10 seconds only
```

Past 10s is discarded. Past 6s shapes the voice but not the delivery. A clip
whose lively passage starts at 0:12 is, for prosody purposes, silence.

| Parameter                    | Target       | Why                                                               |
| ---------------------------- | ------------ | ----------------------------------------------------------------- |
| **pitch movement, first 6s** | **≥ 3.5 st** | decides everything; under 2.8 st stays monotone whatever you tune |
| voiced speech in first 6s    | ≥ 3s         | silence in the window is wasted conditioning                      |
| total length                 | 6–10s        | under 6 starves the encoder, over 10 is thrown away               |
| sample rate                  | 24000 Hz     | `S3GEN_SR`; anything else is resampled                            |
| channels                     | mono         | a stereo mix folds two positions together                         |
| peak level                   | 0.3–0.95     | clipping clones as distortion, quiet clones as noise              |
| speakers in clip             | exactly 1    | a second voice gets blended into the identity                     |
| gap loudness, first 6s       | ≤ −35 dB     | music/noise under the speech is cloned too                        |

Pitch itself is **not** a target: cloning tracks the reference closely, so if it
sounds right to you it will sound right in the app.

The practical consequence: **choose the passage, not just the speaker.** Pick
six seconds where they are animated — arguing, laughing, urgent — and put that
at the very start of the file. A calm, pleasant six seconds is the single most
common way to end up with a companion that sounds dead.

Let `voiceprep.py` find it for you — it scans the whole source, scores every
candidate window by pitch movement, cuts the best one and checks the result:

```sh
python tools/voiceprep.py source.mp3 nova
```

```
  10.3s of audio, scanning for the most expressive 6s ...
  best window starts at 4.0s  (5.25 st, 2.8s voiced)
  VERDICT: expressive (5.21 st). Good reference material.
```

It ignores windows that are mostly silence, so a quiet stretch can't post a high
score on two words. If you would rather cut by hand, `-ss` is the knob:

```sh
ffmpeg -i source.mp3 -ss 00:01:47.5 -t 8 -ac 1 -ar 24000 -sample_fmt s16 \
  -af "silenceremove=start_periods=1:start_threshold=-45dB,loudnorm=I=-18:TP=-2" \
  voices/nova.ref.wav
python tools/voicecheck.py voices/nova.ref.wav     # iterate until >= 3.5
```

## What actually matters

**Pick an animated clip.** Cloning copies _delivery_, not just timbre. This is
the single thing that decides whether your companion sounds alive, and it is
easy to get wrong because a clip can sound perfectly nice and still be flat.

Measured on the same line with identical settings:

| Reference                                                | pitch movement |
| -------------------------------------------------------- | -------------- |
| `s7` (generated by OmniVoice, sounded fine in isolation) | 2.2 st         |
| Chatterbox's own built-in voice                          | **5.3 st**     |

The s7 clone came out monotone, and no amount of `exaggeration`, `cfg_weight`,
seed or temperature tuning fixed it — those knobs moved the number by ~0.3 st.
The reference was the ceiling the whole time. `voicecheck.py` reports this
number so you can reject a clip in two seconds instead of an evening.

Aim for **3.5 st or more**. Below ~2.8 st, don't bother.

**Other things that matter, in order:**

- **One speaker, no music, no reverb, no laugh track.** Anything else in the
  clip gets cloned too.
- **5–20 seconds.** Chatterbox reads up to ~10s; shorter than 5 gives it too
  little to work with.
- **Normal speaking, not shouting or whispering.** Extremes become the baseline
  for _every_ reply, which is rarely what you want.
- **Clean levels.** Clipped audio clones as distortion. `voicecheck.py` flags
  it.

Pitch is _not_ on this list. Cloning tracks the reference's pitch closely, so if
the voice sounds right to you, it will sound right in the app.

## Background music

It hurts twice over.

**It gets cloned.** The encoder conditions on the whole window, so a music bed
becomes part of the voice identity — muddiness, warbling, sometimes tonal
artifacts riding under the speech.

**It corrupts the measurement.** Sustained instrument notes are periodic, so the
pitch tracker scores them as confident pitch. A clip with a bed under it can
report an excellent contour number that is largely measuring the soundtrack.
This is the one case where `voicecheck.py` will flatter a clip it shouldn't.

So the checker reports **gap loudness** — how loud the clip is between words.
Clean dialogue falls away to near silence there; a bed holds it up:

```
clean speech      -56 dB
same speech + bed -24 dB     <- flagged
```

Below −35 dB is clean. Above −20 dB, don't use it. `voiceprep.py` factors this
into its search, so a clean animated passage wins over a noisy one that scores
higher on movement alone.

**What to do about it:**

1. **Pick a different passage.** Dialogue over silence exists in most sources;
   `voiceprep.py` will find it if it's there.
2. **Separate the vocals** — `demucs --two-stems=vocals source.mp3` gives a
   vocals-only track to feed `voiceprep.py`. Good on music, less good on
   dialogue mixed under score, where it tends to leave smearing that then gets
   cloned. Check the result before trusting it.
3. **Don't try to EQ it out.** Music occupies the same band as the voice;
   filtering enough to remove it removes the voice with it.

## Wiring it to a persona

Nothing to wire: `personas/nova.md` speaks with `voices/nova.ref.wav` because
they share a name. The frontmatter is only for tuning — and for `voice:`, when
one clip should serve two personas:

```markdown
---
name: Nova
voice: nova            # only to borrow another persona's clip
temperature: 0.85      # LLM sampling
top_p: 0.9
max_tokens: 160        # cap on reply length
exaggeration: 0.6      # 0-1 delivery intensity
cfg_weight: 0.2        # lower = more pitch movement, slightly less fidelity
---
You are Nova. ...
```

Everything except `name`, `voice` and the body is optional and falls back to
`config.json`. Every key here is measured to do something:

| Key | What it actually changes |
|---|---|
| `temperature`, `top_p` | how varied the words are |
| `max_tokens` | hard cap on reply length |
| `exaggeration` | delivery intensity; each sentence is nudged from it by punctuation and length. **Full Chatterbox only** |
| `cfg_weight` | pitch movement — 0.2 measured more expressive than 0.5. **Full Chatterbox only** |

Turbo is the default and has neither: it takes the words and nothing else, and
warns on every call if the arguments are passed, so the app withholds them and
logs once that the persona's values are doing nothing. To make them work,
download `mlx-community/chatterbox-fp16` and point `tts.model` at it — the app
detects which model is loaded from the path, and the clips are the same for
both, so nothing else changes.

Not exposed, because measurement showed they do nothing here: chatterbox's own
`speed` argument (documented as ignored) and `repetition_penalty` /
`frequency_penalty` (the LLM server accepts and ignores them). Rate was once
done by time-stretching the output; it was removed as unused, and `pause` is
the artifact-free way to slow the feel.

A bad value is logged and skipped rather than crashing the reply. Personas are
re-read before every reply, so you can tune these mid-conversation.

## Auditioning several at once

```sh
for f in voices/*.ref.wav; do python tools/voicecheck.py "$f"; echo; done
```

Keep the ones above 3.5 st, then listen to those — the number tells you what is
_capable_ of sounding alive, not what you will like.

## Engine notes

Full Chatterbox only. `exaggeration` (0-1) sets delivery intensity per
utterance, length is autoregressive, and a short line takes ~0.8-1.0s. Bracketed nonverbal
tags are not its vocabulary and are stripped — write sounds as words (`mmm`,
`ah`) instead.

## When it goes wrong

| Symptom                                      | Cause                                                                                                                                                      |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Monotone, flat, "robotic"                    | Flat reference. Run `voicecheck.py`; if it's under 2.8 st, that's your answer.                                                                             |
| Wrong gender or age                          | Cloning tracks the reference. Get a clip of the voice you actually want.                                                                                   |
| Buzzy or distorted                           | Clipped or noisy source.                                                                                                                                   |
| Voice drifts mid-reply                       | You pointed a reference at generated audio. Always clone from the original clip, never from the app's output — that compounds error and moves the speaker. |
| Sounds like a different person than the clip | Under 5s of reference, or the clip has more than one speaker in it.                                                                                        |

A clip is named after the persona that speaks with it: `voices/<persona>.ref.wav`.
